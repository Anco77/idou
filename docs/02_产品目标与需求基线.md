# idou 产品目标与需求基线

> 状态：规划基线
> 适用范围：从当前 v1.3.7 到“豆仓 + 图纸识别 + 图片转换”完整版本
> 原则：需求编号稳定；实现状态在追踪表中更新，不通过修改需求措辞掩盖未完成项。

## 1. 产品愿景

让拼豆爱好者在一个本地工具里完成：

```text
管理现有豆子
  -> 获取或制作可拼图纸
  -> 核对用量与库存
  -> 开始制作并准确扣库
  -> 保存图纸、进度和成品记录
  -> 重复制作或导出分享
```

## 2. 目标用户与任务

### 2.1 个人玩家

- 快速知道“我有哪些颜色、还剩多少”。
- 拿到一张网上图纸后自动恢复色号与用量。
- 把照片/插画转成一张可编辑、可照着拼的图纸。
- 开做前知道缺哪些豆子，完成后库存自动准确扣减。

### 2.2 高频玩家/手作工作室

- 批量补货、盘点、导入导出库存。
- 保存图纸和重复制作记录，区分“预计用量”和“实际扣库”。
- 用操作流水解释库存为什么变化。
- 在 Windows 上编辑大图，在 Android 上查看和制作。

## 3. 产品目标

### G1 数据可信

任何成功提示都必须对应完整落盘；任何失败都不得留下部分扣库、幽灵图纸或失效路径。

### G2 结果可核对

识别/转换不是黑盒输出。用户能看到网格、色号、数量、低置信度和库存差额，并能修正。

### G3 本地可用

核心豆仓、图纸识别、图片转换、编辑和导出在无网络时可用。网络只用于主动检查更新等非核心能力。

### G4 双端一致

Android 和 Windows 共享领域模型、数据库规则和图像算法；平台差异限制在适配器。

## 4. 关键概念

| 概念 | 定义 |
|---|---|
| 图纸识别 | 从已有网格/色号图纸恢复网格与颜色，不改变原设计 |
| 图片转换 | 从照片/插画生成新的拼豆网格，允许降色、去背景和修图 |
| 图纸草稿 | 尚未保存、可编辑的网格与识别/生成元数据 |
| 图纸 | 已持久化的网格、用量、资源和状态 |
| 库存预检 | 只读比较所需数量和当前库存 |
| 扣库 | 产生库存变动与流水的原子业务操作 |
| 补扣 | 对已保存但未扣库存的图纸执行一次扣库 |
| 冲正 | 用反向流水撤销已发生的库存变化，不删除原流水 |

### 5.2 图纸识别（REC）

| ID | 需求 | 优先级 | 验收摘要 |
|---|---|---:|---|
| REC-001 | 支持相册、文件和相机输入 JPG/PNG | P0 | EXIF 方向正确，输入失败有原因 |
| REC-002 | 自动检测图纸区域、方向、行列与网格边界 | P0 | 输出候选、置信度和结构化失败 |
| REC-003 | 本地 OCR 识别 MARD 色号 | P0 | 字符纠错不破坏系列首字母；非法码拒绝 |
| REC-004 | 颜色采样作为 OCR 兜底 | P0 | 与 OCR 使用相同坐标；记录色差与来源 |
| REC-005 | 正确识别空白格与白色豆子的差异 | P0 | 空格不计用量；标注白色豆仍能识别 |
| REC-006 | 融合 OCR、颜色和邻域一致性 | P0 | 每格有最终颜色、来源和置信度 |
| REC-007 | 质量门禁阻止低质量结果直接扣库 | P0 | 用户确认或修正前扣库按钮不可用 |
| REC-008 | 识别过程不阻塞 UI，并可取消 | P1 | 52×52 处理中滚动/返回可响应 |
| REC-009 | 自动失败后提供明确拍摄建议 | P1 | 不只显示异常字符串 |

说明：当前工作区加入了手动行列兜底，但历史 v1.4 基线明确禁止。该项归为 P2 候选，P0 期间不以手动参数掩盖自动识别失败。

## 6. 非功能需求

### NFR-01 正确性

- 库存不得为负。
- 图纸用量必须等于网格非空格聚合结果。
- 任何库存变化都必须有流水，任何图纸扣库流水都必须有 `patternId`。

### NFR-02 性能

- 221 色库存首页首次查询目标 < 300 ms（不含应用冷启动）。
- 52×52 编辑操作目标 < 50 ms；104×104 目标 < 100 ms。
- 图像任务运行在 isolate；进度更新不超过每 100 ms 一次。
- 初始识图目标：52×52 < 3 s、104×104 < 8 s（中端 Android，清晰数字图）。

### NFR-03 可靠性

- DB 迁移失败不破坏旧库，并给出可导出的诊断信息。
- 写入媒体使用临时文件 + 原子重命名。
- 备份恢复前验证 schema、manifest 和文件哈希。

### NFR-04 隐私

- 图片默认只在本地处理和保存。
- 不上传图纸、库存、完成照或诊断数据。
- 网络更新请求与核心数据隔离。

### NFR-05 可测试性

- Domain/Application 不依赖 Flutter binding。
- OCR、文件系统和时钟均有可替换接口。
- 每个 P0 用例至少有成功、业务失败、基础设施失败和回滚测试。

### NFR-06 可访问性

- 颜色信息不能只靠色块表达，必须同时显示色号/文本。
- 关键按钮触控区域 ≥ 44×44。
- 支持系统字体缩放和深色模式。

## 7. 明确不做

首个完整版本不做：

- 社区、关注、评论、付费内容和商城。
- 账号、云同步和多人协作。
- 云端生成式 AI。
- 多品牌色卡同时编辑；先把单一 MARD 221 闭环做稳。
- 3D 熨烫效果和 AR 预览。

这些能力不阻止未来扩展，但不能进入当前核心链路的依赖。

## 8. 成功指标

### 工程指标

- `flutter analyze` 0 error，新增代码不增加 warning。
- 全部自动化测试通过；schema 迁移测试覆盖 v1/v2。
- P0 业务用例事务失败注入测试 100% 通过。

### 算法指标

- 干净合成图网格检测成功率 ≥ 98%，逐格色号准确率 ≥ 97%。
- 扫描/截图扰动集网格成功率 ≥ 95%，逐格准确率 ≥ 90%。
- 首批真实图纸网格成功率 ≥ 90%，逐格准确率 ≥ 85%；低于门槛时必须正确阻止自动扣库。

### 产品指标

- 新用户从初始化豆仓到完成一次单色操作 ≤ 2 分钟。
- 清晰图纸从选择到可编辑结果 ≤ 4 个动作。
- 保存并扣库后，用量、库存与流水对账差异为 0。
