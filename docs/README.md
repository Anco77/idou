# idou 项目文档

本目录是后续研发使用的主文档入口。文档基于 `main@958a3f5`、当前未提交工作区和 2026-08-11 的代码审计结果编写。

## 阅读顺序

1. [项目总览与现状审计](00_项目总览与现状审计.md)：项目现在是什么、实际完成到哪里、主要问题在哪里。
2. [目标架构](01_目标架构.md)：后续代码应收敛成什么结构，以及关键业务边界如何划分。
3. [产品目标与需求基线](02_产品目标与需求基线.md)：产品目标、范围、需求编号与验收规则。
4. [实施计划书](03_实施计划书.md)：阶段、依赖、交付物、质量门禁和风险处理。
5. [AI 全流程执行计划](04_AI全流程执行计划.md)：AI 如何逐项领取、开发、测试、验证、交付和续跑。
6. [`AI_TASKS.yaml`](AI_TASKS.yaml)：机器可读的任务依赖、状态、验收条件和门禁。
7. [AI 执行日志](AI_PROGRESS.md)：每次执行的证据与下次入口。
8. [发布清单](RELEASE_CHECKLIST.md)：候选版本从验证到 Git/制品发布的签字表。
9. [当前工作区验收基线](WORKTREE_BASELINE.md)：未提交改动的唯一任务归属、状态分类和后续验证矩阵。
10. [Android 发布签名管理](ANDROID_SIGNING.md)：仓库外密钥位置、证书指纹、构建和灾备要求（不包含密码）。

## 文档状态约定

- `现状`：已经在当前代码中存在，仍可能有缺陷。
- `已改未验收`：当前工作区已经有修改，但尚未通过静态分析、测试和样本验证。
- `目标`：已确定的设计方向，尚未实现。
- `候选`：需要通过样本、技术验证或产品反馈后再决定。

## 与历史文档的关系

工作区外层 `../docs/` 中保留了历史需求、修改方案和 v1.4 基线。它们是重要输入，但存在版本范围冲突和状态过期。自本轮规划后：

- 产品范围以 [产品目标与需求基线](02_产品目标与需求基线.md) 为总基线。
- 技术边界以 [目标架构](01_目标架构.md) 为准。
- 排期与验收顺序以 [实施计划书](03_实施计划书.md) 为准。
- 历史文档不删除，仅作为决策记录和问题来源。
