# idou 版本策略

## 单一事实源

- `pubspec.yaml` 的 `version: MAJOR.MINOR.PATCH+BUILD` 是应用构建版本的事实源。
- `version.json.latest` 必须与 `pubspec.yaml` 的前三段版本一致；它服务于更新检查和发布元数据。
- 数据库 schema 版本由 Drift 数据库源代码维护，schema 迁移必须单独记录，不能通过改应用版本掩盖迁移缺失。

## 递增规则

- `PATCH`：兼容性修复或小范围体验修复。
- `MINOR`：新增兼容功能或完成一个计划阶段。
- `MAJOR`：不兼容的数据或用户流程变更。
- `BUILD`：每次可分发构建递增；不作为功能版本判断依据。
- 预发布版本使用 `-alpha.N` 或 `-beta.N`，不得复用已经发布的稳定版本号。

## 发布一致性

发布前必须同时核对 `pubspec.yaml`、`version.json`、schema 版本、变更日志、产物文件名和校验值。版本、schema 或升级测试任一不一致时，不得创建 tag 或上传产物。

当前基线：应用 `1.3.7+1`，公开元数据 `1.3.7`，目标整体版本 `1.4.0`。历史上的旧 `v1.4.0` 标签已清理；只有 S6-04 发布门禁全部通过后，才可在当前交付提交上重新创建 `v1.4.0`。
